Networks autograder

Black-box Gradescope autograders for the CSCI 471/560 networking projects. Each student's C/C++ submission is built with its own Makefile, run as an unprivileged user, and tested from the outside through its CLI, files and sockets. A small pytest plugin turns pytest results into Gradescope's results.json.

Reusable layer: pytest plugin (gs marker, score fixture, results writer), build/unpack logic, sandboxed process runner, Gradescope entry scripts.

    Grading pipeline, end to end

    What happens from "student uploads" to "score appears". Gradescope runs setup.sh once when building the image, then run_autograder per submission.

    Plugin and scoring framework/plugin.py

    A pytest plugin with no dependencies beyond pytest. Tests declare Gradescope metadata with a gs marker and use a score fixture for partial credit and student-visible text.

    The gs marker

    @pytest.mark.gs(weight=5, name="GET /file1.html returns 200",
                visibility="visible", number="1.1", tags=[...], variants=["560"])
def test_get(executable, workdir, score):
    result = proc.run([executable, ...], cwd=workdir, timeout=10)
    score.log("shown to the student")
    score.set_fraction(0.5)                                # optional partial credit
    pytest.fail("short student-facing reason", pytrace=False)
    Marker merging (gs_meta)

    Walks item.listchain() from outermost to innermost node and dict.updates each gs mark's kwargs, so closer wins:

    modulepytestmark→class→function→pytest.parammarks=

    P4 uses the last level: each case's weight, visibility and name come from its meta.json via pytest.param(marks=gs(...)).

    Display names (_display_name)

    Name comes from gs(name=), else the first docstring line, else the function name. For parametrized tests, {id} is substituted if present, otherwise " [id]" is appended.

    Variants

    --gs-variant (or AUTOGRADER_VARIANT) in pytest_collection_modifyitems. A test with variants=["560"] is deselected unless the variant is 560. Tests without variants always run.

    Scoring rules: try it

    Logic mirrors _Entry.to_json: skipped (and not failed) → 0; else an explicit score.set value (clamped to [0, weight]) wins even if the test failed afterwards; else full weight on pass, 0 on fail. Status is "passed" only when not failed, not skipped and points ≥ weight.

    What students see

    Exception in testStudent-facing output
    pytest.fail(msg)msg
    AssertionErrorthe assertion message, or "Assertion failed."
    pytest.skip(msg)"Skipped: msg", scores 0
    anything else (call/setup)generic INTERNAL_ERROR_MSG + exception type name
    anything else (teardown)INTERNAL_ERROR_MSG + "(cleanup: Type)"

    Output per test = failure messages then score.log lines, joined with blank lines and truncated to 10,000 chars by truncate(), which keeps the first ⅔ and the tail so students see both ends. If pytest exits INTERRUPTED / INTERNAL_ERROR / USAGE_ERROR / NO_TESTS_COLLECTED, a top-level "did not run to completion" banner is prepended (and score: 0 if no tests ran). pytest_terminal_summary prints a PASS/FAIL scoreboard for instructors.

    The dependency graph a test pulls in. Blue boxes are framework-provided, green are project-provided.

    build wraps build_submission in a broad except: a harness bug prints a traceback for instructors and returns a failed BuildResult with a neutral message, so it never looks like a silent student build failure. workdir names each directory after the test's nodeid, sanitized to [A-Za-z0-9_.-] and cut to the last 120 chars, under work_root()/tests/.

    Build and submission handling framework/build.py

    Students are told to submit username.tgz containing username/Makefile, but Gradescope uploads arrive in three shapes. prepare_submission handles all of them.

    Project is a tiny dataclass: name, executables (first is "primary"), build_timeout=120, make_args=(). Unit tests in framework/tests/test_build.py cover all three layouts, the no-Makefile message, and path-traversal rejection.

    Process sandbox framework/proc.py

    proc.run(cmd, *, cwd, timeout, stdin=None, env=None, privileged=False) → RunResult is the only way student code is executed.

    Isolation
    • start_new_session=True: own process group; on timeout and after normal exit the whole group gets SIGKILL, so forked children can't outlive the test.
    • preexec_fn=_limits: RLIMIT_FSIZE 64 MiB, RLIMIT_CORE 0.
    • Runs as student uid/gid with extra_groups=[] unless privileged.
    • Minimal env: PATH, HOME=cwd, LANG/LC_ALL=C.UTF-8, plus env extras.
    • stdin is DEVNULL unless bytes are given.
    Bounded capture

    stdout/stderr go to anonymous temp files, not pipes, so a chatty program can't deadlock or exhaust memory. Only the first 1 MiB of each is read back, then "[output truncated by autograder]".

    RunResult.describe(tail)

    Student-facing summary: "did not finish within N s and was killed", "crashed (SIGSEGV)", or "exited with status N", plus the last tail chars of stderr. returncode is None on timeout.

    Security model

    On Gradescope the harness runs as root. Student code must never be able to read the tests, the expected outputs, or tamper with results.

    config.student_user() only returns a user when AUTOGRADER_STUDENT_USER is set and the process is root; locally everything runs as you. work_root() prefers AUTOGRADER_WORK_DIR, then /autograder/work if writable, else a temp dir.

    Project 4: Routing project-autograders/p4_routing/

    Students write router -c interfaces.txt -r routes.txt [-i input] [-o output] [-d level], which prints the egress interface and next hop for each destination using longest-prefix match. Grading compares output line by line against outputs generated by reference.py.

    Routing semantics (reference.py)

    1. Trim lines; skip blanks and lines starting with #.
    2. Find the longest-prefix connected interface subnet containing the destination.
    3. Find the longest-prefix static route; on a tie the earlier line wins (strict >).
    4. If connected exists and its prefix ≥ the route's, it wins: dest: iface -> dest.
    5. Otherwise use the route; egress is the longest-prefix interface containing the next hop: dest: iface -> hop.
    6. No match: dest: unreachable.
    Comparison (compare.py)

    Regex: IP:\s+(unreachable | iface\s+->\s+IP). Lines are normalized (any whitespace run accepted), then compared positionally.

    fraction = max(0, (correct − extra) / expected)

    Extra lines cost one line each so spamming output can't help. 1.2.3.4 : eth0 or => are not tolerated. The stdin/stdout test uses parseable_lines to ignore debug output mixed into stdout.

    Test cases

    All cases run with -d 0 and a 10 s timeout. Visible cases sort to the top. Hand cases are authored in make_cases.py; random cases use seeds 471 and 598 (8 interfaces, 40 routes, 150 destinations). Random generation never creates two entries with the same network (no ties), and skips routes more specific than a connected subnet, because the spec is ambiguous there. Every next hop sits on a connected subnet. tests/test_p4_routing.py asserts the reference reproduces every committed output.txt.

    Project 3: Traceroute project-autograders/p3_traceroute/

    Students write traceroute -t DEST [-d level] using raw sockets and hand-built IPv4 + ICMP Echo Requests, starting at TTL 2. Real raw sockets need root and internet access, so the grader fakes the network with an LD_PRELOAD shim.

    How the simulated network works (tracesim.c)

    Routers reply with ICMP Time Exceeded (type 11) quoting the datagram as they saw it (TTL rewritten to 1, per RFC 1812). The destination replies with Echo Reply echoing id/seq/payload. For IP_HDRINCL sockets the shim fills total length, IP id, source and destination when zero, and the IP checksum, as the kernel would. The simulated local address is 10.0.2.15. Noise is an Echo Reply from 198.51.100.77, an Echo Request from .88, and a Destination Unreachable from .23 about an unrelated flow to .99. A statically linked binary bypasses the shim; the trace fixture detects the missing init event and says so.

    Scenarios (sim.py)

    Each row shows what answers at each TTL. The student should send TTL 2 first; TTL 1 is greyed out. Hover a hop for details.

    Tests and weights

    The trace fixture runs each scenario once per session and caches it, so 12 graded tests cost only 5 real runs, plus up to 7 extra -d runs. Router order is checked with a longest-common-subsequence (lcs_len) over IPs found in output, so extra text and timings don't matter but order does. A correct submission takes about 50 s because silent hops really wait 15 s. Set the Gradescope timeout to at least 10 min.

    Selfcheck: grading the grader framework/tools/selfcheck.py

    Each project ships a reference solution with #ifdef BUG_* switches. For every variant in variants.json, selfcheck packages the zip, builds student1.tgz with Makefile.template's @DEFINES@ replaced by -DBUG_…, runs run_autograder with all paths redirected to a temp dir, validates the JSON schema, and checks expectations.

    Expectations: expect_total "full" or "zero"; expect_pass/expect_fail are substrings of test names. Every matching test must have that status, and at least one must match. include_junk_binary plants a fake router and router.o to prove prebuilt files get deleted.
